20 October 2026, Asia/Calcutta. Baseline `fe5d4c4`. User authorizes sequential
eligible work. This narrow task searches public producer documentation for an
original-name, independently benign client-query source and legitimate service
categories. Search/catalogue/paper/README metadata only; at most three new leads
are investigated in this work package. Existing reviewed leads are not new data.

Keep the existing DGA protocol and all four promotion gates byte-identical.
Exactly five strata of 600 labels and a separate >=2,500-label DNS role remain
required. Source-supported benign intent and categories, original DNS name
semantics, separate source identity, public permission and accessible compatible
format must be documented before acquisition or any count. Do not interpret
popularity, absence from a blacklist or unlabelled background as verified benign
client activity. Per-role counts/overlaps stay unverified without an approved
integrity-only count; published rows are not eligible first labels.

Do not open domain files, packet values, data viewers, examples/test vectors,
models or new scoring outcomes. Do not execute source code, acquire bulk data,
train, tune, promote, change roles/exclusions/gates or request private supplements.
If search snippets or documentation incidentally expose DNS-like strings, record
them as development-document exposures for later exclusion, never as reserve.
Preserve all original data, analyst history, artifacts and current 130-file pins.

Output source-specific provenance/access/format limitations and qualification
status, document bytes/identities where retrievable, integrity checks and one
smallest next action. Stop this track on missing provenance rather than making
labels or running another model experiment. A negative bounded search is not
proof that no suitable source exists. No full backend/build rerun is necessary
for a metadata-only package; do not relabel previous results as fresh tests.
