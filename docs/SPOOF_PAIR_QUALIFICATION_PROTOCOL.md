# T22 forged/genuine UDP development-pair qualification protocol

Frozen 17 October 2026 against 949e697, after prior diagnostic and initial
publisher search excerpts, before new capture/flow/annotation values. Qualification
only; no detector experiment, fitting, inference, ablation, activation or reserve.

Screen a bounded set of at most five candidate producer/source families, using
primary documentation and artifact metadata only. Keep already exposed simulations
as failed development controls. Do not download arbitrary captures because a file
name says spoof/flood/benign. All consulted leads are development-influenced and
cannot be relabelled untouched C2/DDoS final evaluation.

Mandatory provenance before value inspection:
1. Applicable capture-data permission and attribution, fixed release, exact original
   artifact/member URLs and SHA256. Original complete classic Ethernet PCAP v2.4,
   linktype1, compatible with current reader; header/format verification may occur
   only after source permission/run labels/service/time prerequisites pass.
2. Two independently producer-labelled lab runs, one with deliberate source-address
   forgery and one genuinely distributed authorized application workload. Require
   emitter/ownership assignment and topology/run records independent of timing,
   entropy, TTL, reputation, Univect or other detector outputs. An hping3 mention,
   UDP/DDoS category or claimed victim-side reflection trace is insufficient.
3. Capture placement/direction showing exactly which observed packet sources were
   deliberately forged. Reflector replies can have genuine reflector addresses;
   forged requests elsewhere do not label those replies as forged.
4. Same actual UDP application/service AND destination port; real benign clients,
   documented distributed emitter population, endpoint/direction joins, producer
   run boundaries, original UTC/offset and clock/reordering provenance. Background
   traffic or randomized addresses do not by themselves verify genuine owners.
5. No payload stripping, timestamp/address rewriting or synthetic frame conversion
   to repair an incompatible release. Record loss, truncation, fragments, duplicates,
   ordering and unknowns. No new parser/format support or traffic generation.

If prerequisites pass, bind the exact two runs and artifact/annotation hashes BEFORE
values. Reuse the fixed same-service UDP load screen: UTC-aligned one-second counts,
all complete nonoverlapping ten-second blocks inside producer intervals, at least
three blocks with >=1000 packets/s per run; packet-rate ranges overlap with positive
width and pooled IP-length IQRs intersect (endpoints inclusive). Preserve and report
all blocks and failures. This is a data-matching screen, not a new detector gate.
Do not rescale timestamps, rewrite ports, duplicate/relabel traffic or select by
alerts. A pair cannot establish accuracy, forgery proof or promotion.

Only then compare existing forward passive metadata/features and surviving
collisions, without prediction. Ownership labels stay annotations, not predictors.
No probes, return-path dependency, inline mitigation, DNS/reputation lookup,
TLS/QUIC decryption, new infrastructure, model/rule changes or external messages.
No mailbox monitoring or new recipient contact in this task.

Existing frozen subtype gates unchanged: recall>=80%, precision>=95%, FPR<=2%,
early positive indications and matched-benign discrimination. Historical
TP4/TN2/FP4/FN0; failed predicate stays disabled. Preserve all other detector
partitions/protocols, raw sources, artifacts and analyst history.

Stop on missing/ambiguous provenance, permission, original supported capture,
source ownership/capture-placement truth, matched service or load overlap.
Qualification DoD requires one verified pair and measured overlap with reproducible
provenance. Otherwise mark BLOCKED_NOT_QUALIFIED and stop; do not force completion.
